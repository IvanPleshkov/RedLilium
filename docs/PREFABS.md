# Префабы: замечания к текущему механизму

Рабочие заметки по слабым местам системы префабов. Зафиксированы перед тем,
как заняться самими префабами. Сначала планируется «копнуть» в некоторые
компоненты — поэтому это справочный список, к которому вернёмся.

Контекст: сцена по сути = большой префаб. Пока префабы не устроят полностью,
сериализовать сцену смысла нет (это тот же префаб). Значит префабы — несущая
задача для сохранения/загрузки сцены, in-place редактирования и идеи
«Play = закрыть редактор + запустить игровой процесс».

## Как устроено сейчас

- **Префаб = запечённый снимок поддерева.** BFS по `Children` от корня.
  - In-memory: `Prefab` хранит `Vec<(Entity, Vec<Box<dyn ComponentBag>>)>`
    ([ecs/src/prefab.rs:90](../ecs/src/prefab.rs#L90)).
  - Сериализованный: `SerializedPrefab { entities: Vec<SerializedEntity> }`,
    где `SerializedEntity` = `entity_index` + `entity_spawn_tick` + `entity_flags`
    + `Vec<SerializedComponent { type_name, data: Value }>`
    ([ecs/src/serialize/prefab_io.rs](../ecs/src/serialize/prefab_io.rs)).
- **Компоненты опт-инятся** в (де)сериализацию через `serialize_fn` / `deserialize_fn`,
  регистрируемые на тип компонента
  ([ecs/src/world/component_ops.rs:106](../ecs/src/world/component_ops.rs#L106)).
- **Ссылки между сущностями** (`Parent`/`Children`/кастомные через
  `collect_entities`/`remap_entities`) ремапятся по
  `(исходный index, spawn_tick) → новая сущность` в пределах набора
  ([ecs/src/world/inspector.rs:461](../ecs/src/world/inspector.rs#L461)).
- **Инстанцирование = спавн свежих копий** + ремап + вставка; разделяемые `Arc`
  дедупаются через кэш контекста
  ([ecs/src/prefab.rs:143](../ecs/src/prefab.rs#L143),
  [ecs/src/world/inspector.rs:453](../ecs/src/world/inspector.rs#L453)).
- **Ассеты (меш/материал) — по строковому имени** в менеджерах: сериализуется
  имя, на загрузке резолвится из `MeshManager`/`MaterialManager`
  ([ecs/src/std/rendering/components/render_mesh.rs:53](../ecs/src/std/rendering/components/render_mesh.rs#L53)).

## Замечания

### 1. Это «штампы», а не связанные инстансы  (приоритет: высокий)
У инстанса нет ссылки на исходный префаб. Следствия:
- правка источника не распространяется на инстансы;
- нет пер-инстансных оверрайдов (дельт поверх префаба).

В Unity/Godot — связанные инстансы + сохраняемые дельты оверрайдов. Здесь
`instantiate`/`deserialize_prefab` просто спавнят независимые копии
([ecs/src/prefab.rs:143](../ecs/src/prefab.rs#L143)).

### 2. Нет стабильных ID (GUID)  (приоритет: высокий)
Идентичность в файле — `index + spawn_tick` исходного мира, годная только для
внутреннего ремапа ссылок
([ecs/src/world/inspector.rs:461](../ecs/src/world/inspector.rs#L461)).
Нет долговечного ID, чтобы:
- ссылаться на сущность между файлами;
- делать оверрайды (нужен якорь «эта сущность = тот элемент префаба»);
- мержить / делать 3-way diff;
- держать ссылки стабильными между пересохранениями.

Замечание #1 без #2 в принципе не сделать.

### 3. Нет вложенности префабов  (приоритет: средний)
Инстанс префаба, положенный в сцену или в другой префаб, расплющивается в сырые
сущности — факт «это поддерево — инстанс префаба X» теряется. Сцена не может
хранить инстансы префабов, только запечённые копии. Следствие отсутствия #1/#2.

### 4. Ссылки на ассеты по строковому имени  (приоритет: средний)
Меш/материал резолвятся по имени из менеджера
([render_mesh.rs:57](../ecs/src/std/rendering/components/render_mesh.rs#L57)):
- ломается при переименовании ассета;
- требует, чтобы менеджеры на загрузке были засеяны теми же именами;
- нет идентичности ассета по пути/GUID.

### Помельче
- **Молчаливая потеря данных:** неизвестные / несериализуемые компоненты тихо
  пропускаются на round-trip
  ([ecs/src/world/inspector.rs:509](../ecs/src/world/inspector.rs#L509),
  [ecs/src/prefab.rs:70](../ecs/src/prefab.rs#L70)).
- **Запекание флагов:** `entity_flags` (включая `EDITOR`) попадают в префаб
  ([ecs/src/world/inspector.rs:475](../ecs/src/world/inspector.rs#L475)). Для
  «сцена = префаб» редакторские сущности, вероятно, надо исключать.

## Вывод по приоритетам
Ключевые — **#1 (связанные инстансы + оверрайды)** и **#2 (стабильные GUID)**:
без них не строятся ни сцена из переиспользуемых префабов, ни нормальное
редактирование/мерж. #3 и #4 — следствия, их проще решать после #2.

## Статус
Сначала разбираемся с некоторыми компонентами, затем возвращаемся к префабам.
