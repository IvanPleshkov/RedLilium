# Remote control (editor automation)

Канал управления редактором для инструментов и агентов (в первую очередь —
Claude): текстовый протокол, через который можно читать состояние сцены,
совершать undo-able правки и снимать скриншоты. Дизайн-цели: пригодность для
слабых моделей (плоские текстовые команды, предсказуемые ответы), соблюдение
редакторской гарантии (все правки — через `EditAction` → история), явная
асинхронность ассетов.

## Транспорт

- TCP на localhost; порт выбирается ОС и публикуется в `.redlilium/editor.port`.
- Включается только `REDLILIUM_REMOTE=1` (по умолчанию канала не существует).
- Сеть обслуживается IO-рантаймом движка (тем же tokio, что грузит ассеты):
  транспорт — `RemoteTransport` (ресурс) + `RemoteServe` (система), движковый
  уровень (`ecs/std/remote.rs`); семантика команд — в редакторе
  (`editor/src/remote_commands.rs`).
- Это dev-инструмент: без аутентификации, не игровой неткод.

## Формат

Одна строка — один запрос; одна строка — один ответ. Всё — RON.

```
(id: 1, cmd: "inspect", entity: "12@3")
(id: 1, ok: true, entity: "12@3", components: [("Transform", (translation: (…), …)), …])
```

- `id` — корреляция; ответы приходят по порядку в рамках соединения.
- Ошибка: `(id: N, ok: false, error: "…")`. Неизвестная команда — ошибка,
  не обрыв.
- **Естественный RON**: данные компонентов — обычные RON-значения (то, что
  написал бы человек), без внутреннего тегированного дерева и без
  строкового экранирования. Числа терпимы к форме (`1` / `1.0`) — serde
  приводит к типу поля. Ссылки на сущности: `(__entity: "index@tick")`.
- Сущности адресуются как `"index@spawn_tick"` (стабильно в рамках сессии;
  видно в `state`).

## Семантика исполнения

- **Записи** (`edit_component`, `add_component`, `remove_component`,
  `select`) строят те же `EditAction`'ы, что и UI, и идут через
  `ActionQueue` → историю (undo работает). Ответ приходит **после
  применения** (следующий кадр) и несёт свежий снапшот затронутого
  компонента.
- Ответ на запись НЕ означает, что ассеты доехали. Асинхронность явная:
  `wait(for: "assets_idle")` ждёт, пока ассет-пайплайн будет спокоен
  несколько кадров подряд. Рецепт проверки: `edit` → `wait assets_idle` →
  `screenshot`/`inspect`.
- **Чтения** отвечают в том же кадре.

## Команды (proto 1)

| Команда | Параметры | Ответ |
|---|---|---|
| `hello` | — | `proto`, `commands` |
| `state` | — | `entities: [(entity, name, parent, components)]`, `selection` |
| `inspect` | `entity` | `components: [(имя, натуральный RON)]` |
| `edit_component` | `entity`, `component`, `data: <RON>` | снапшот компонента после применения |
| `add_component` / `remove_component` | `entity`, `component` | ack после применения |
| `select` | `entities: […]` | ack после применения |
| `undo` / `redo` | — | ack / ошибка |
| `logs` | `since` (seq) | `entries: [(seq, level, target, message)]` |
| `wait` | `for: "assets_idle"` (+`timeout_ms`) \| `for: "frames"`, `n` | ack по условию / timeout |
| `screenshot` | `target: "scene"`, `path` | `path`, `width`, `height` — PNG написан на диск |

Скриншот делается GPU-ридбеком текстуры сцены через frame graph (бинарь в
протокол не заходит — редактор пишет PNG в файл и возвращает путь).

## CLI

`cargo run -p redlilium-editor --bin editor_ctl -- <cmd> [...]` — сахар над
протоколом (см. шапку `editor/src/bin/editor_ctl.rs`). Одна команда — одно
соединение — одна строка ответа. `raw '(…)'` шлёт произвольный конверт.

## Эволюция

Протокол версионируется числом в `hello`; развитие аддитивное. Зарезервировано
на следующие срезы: `step N` (tick-on-demand в headless), `pick x y`
(сущность под точкой через picking-пасс), `input` (инъекция ввода),
`new_asset` / `drop_asset`, `play` / `stop`. Headless-режим редактора
(рендер в текстуру без окна) — отдельный срез, протокол не меняется.

Планка на будущее: **любое** действие AbstractEditor должно быть доступно
через канал. Путь: действия конструируются из параметров, undo-состояние
захватывается в `apply` (так уже устроены Remove/Import) — тогда любое
действие десериализуемо; реестр `имя → десериализатор` поверх этого.
